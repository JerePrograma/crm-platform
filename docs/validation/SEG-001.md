## Causa raíz Jackson confirmada

Spring Boot 4.1 administra Jackson 3.1.4 y registra
`tools.jackson.databind.ObjectMapper`. `AuditEventWriter` y
`ProspectImportRowProcessor` todavía importaban tipos Jackson 2
`com.fasterxml.jackson`, por lo que el bean administrado no era asignable al
constructor de auditoría.

El árbol también contiene Jackson 2.21.4 por springdoc/Swagger, pero esa familia
es una compatibilidad transitiva de terceros, no el mapper propio de la
aplicación.

## Corrección ejecutada

```text
f39e881 fix: align audit JSON serialization with Spring Boot 4
6f0bafb style: apply backend formatter
41a1548 fix: support current Docker API in backend verification
951d19b fix: use IPv4 frontend health check
d8a5a44 build: lock frontend dependencies
```

El código propio usa Jackson 3, conserva el mapper administrado por Spring,
persiste payloads mediante `CAST(? AS jsonb)` y convierte timestamps JDBC al
tipo SQL explícito. La regresión usa un contexto Spring/Testcontainers real y
lee el JSON persistido con el mismo mapper.
