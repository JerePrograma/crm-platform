# SEG-001 — Vertical slice persistente de prospectos

## Estado

`ACTIVE — IMPLEMENTATION_SUBSTANTIALLY_COMPLETE / VALIDATION_PENDING`

No debe marcarse `COMPLETE` hasta observar una ejecución limpia de backend, frontend, Flyway/Testcontainers, Compose e imagen Docker.

## Objetivo

Entregar un recorrido real y seguro desde archivos CSV/XLSX hasta PostgreSQL, con prospectos consultables, exclusiones dominantes, deduplicación, revisión humana, auditoría e interfaz operativa. Ningún envío real forma parte del segmento.

## Riesgos

1. la rama acumula muchos commits pequeños por limitaciones del conector; antes de PR puede convenir squash controlado;
2. no existe lockfile frontend;
3. HTTP Basic es solo bootstrap de desarrollo;
4. la API de exclusiones todavía muestra valores completos a cualquier usuario autenticado;
5. no existe resolución auditada de revisiones;
6. un ImportJob fallido no puede reintentarse con el mismo SHA/modo;
7. el esquema considera una institución = un prospecto;
8. la auditoría no tiene actor todavía porque falta identidad persistente;
9. no existe política de retención;
10. el lote real disponible cubre 100, no 298 prospectos.
